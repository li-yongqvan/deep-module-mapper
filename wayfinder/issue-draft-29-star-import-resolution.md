# Issue 草稿 #29：星号导入符号解析（两趟解析 + 符号表）

> 状态：**已发布为 issue #29**（2026-09-06）。关联：#28 子项 B（止血）的根治姊妹票。

## 标题

星号导入符号解析：两趟解析建跨文件符号索引，根治 `from x import *` 的 unresolved_symbol

## 背景

狗粮实测（2026-09-06）：`from x import *` 使解析器无法知道搬进了哪些名字，**每个使用点**各报一条 `unresolved_symbol`——QuickCut 586 条、you-get 1626 条，真实信号被淹没。#28 子项 B 做的是「降噪止血」（按星号导入聚合成一条）；本票做**根治**：把能静态解析的星号导入真正解析掉。

「无法解析」并非全是死局，分三层：

1. **静态可解（本票目标，占实测案例 100%）**：AST 可见 import 语句；顺着 import 找到被导入模块，读其模块级定义（`def`/`class`/赋值/`__all__`），即可确定星号导入搬进来的名字集合——纯静态、不跑代码。
2. **真静态无解（保持报诊断，宁缺勿幻）**：运行时动态注入（`setattr` 造属性、`globals()` 注入、C 扩展内置名）。少见，维持现有诊断即可。

## 现状与约束

- parser 当前**单文件、无状态**：扫 `a.py` 不读 `b.py`，这是当初「零第三方依赖 + 秒扫」的取舍。
- 不变量（红线）：parser 零第三方运行时依赖；「宁缺勿幻」原则不破（解析不了宁可不造边，不造幻觉边）；既有 5 键 golden 逐字节一致；第 6 键 `intra` 契约不回退。

## 方案方向（供设计参考，非既定方案）

**两趟解析**：
1. **Pass 1 · 符号索引**：扫描全部模块，建「模块 → 模块级公开符号表」索引（含 `__all__`；无 `__all__` 则取非 `_` 前缀的顶层定义；import 绑定的再导出规则需定义）。
2. **Pass 2 · 消解**：解析 import 边时，星号导入按索引展开为具体符号，使用点可解析则不再报 unresolved_symbol，并可为跨模块符号引用建立更精确的边/端口归属。

待设计决策（grilling 时定）：`__init__.py` 再导出的传递性；条件定义/同名重定义的索引口径；循环导入下索引的健壮性；两趟的缓存与增量（重扫成本）。

## 验收方向

- you-get 扫描的 `unresolved_symbol` 从 1626 降至「仅剩真动态注入」量级（预期 <10）；
- golden 测试扩展前后 5 键逐字节一致（本票动了边的精度，需评估 golden 是否应同步演进——这是设计文档要回答的）；
- 新增单测：星号导入展开、`__all__` 尊重、`_` 前缀排除、跨包子包星号导入、遮蔽场景仍宁缺勿幻、循环 import 不崩。
